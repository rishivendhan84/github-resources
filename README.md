## What this is

Most "awesome" lists are graveyards: a wall of links dumped once and never touched. This one is different in two ways:

1. **[The Index →](github-resources.md)** — 170 hand-picked repos and topic hubs across **16 domains** (AI agents, LLMs & RAG, generative AI, computer vision, NLP, recommenders, RL, full-stack, mobile, security, blockchain, MLOps, IoT, DevOps, research, game dev). Each entry is a real project you can build, fork, or learn from.
2. **[The Teardown Log →](teardowns/)** — every day, 3 trending repos + 1 public knowledge vault get pulled, triaged in 10 minutes, and given a verdict. It's the list *staying alive* instead of rotting.

**Who it's for:** developers looking for their next project, engineers dropped into an unfamiliar domain who need a reference implementation fast, and anyone who wants a shortlist instead of a search results page.

## The 60-second teardown trick

Swap `github.com` for `gitingest.com` in **any** repo URL and you get the entire repository as a single text blob — ready to paste into an LLM for a first-pass explanation.

```
https://github.com/langchain-ai/langchain
        ↓  swap the domain
https://gitingest.com/langchain-ai/langchain
```

That one substitution is what makes reading a repo a day sustainable. Try it on any link in [the index](github-resources.md).

## How the daily scan works

Every morning the scan pulls `github.com/trending?since=daily` plus a rising-repo search, filters to a working set of lanes (AI agents, MCP, LLM tooling, automation, frontend/AI), and keeps the **top 3 repos plus 1 public knowledge vault**.

Each pick gets a 10-minute triage and one of four verdicts:

| Verdict | Meaning |
|---|---|
| `teardown` | Worth a full write-up |
| `toolbox` | Worth reusing in real work |
| `vault-study` | Structural patterns worth stealing |
| `dropped` | No further action |

At most **one repo per day** is promoted to a real timeboxed exploration. Five candidates a day against a one-per-day follow-through rate only ever grows a backlog — so the cap is three. See the running log in **[teardowns/](teardowns/)**.
